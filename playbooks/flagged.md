# Playbook: проверь проблемные

Пользователь помечает в UI ⚑ «Проблемная» (`flagged: true`) вакансию, где, по его мнению, неверный скоринг или данные;
причину он обычно пишет в `notes`. Задача агента — разобрать, исправить, сохранить вывод и снять флаг.

1. Список: `grep -rl '^flagged: true' data/vacancies`.
2. Для каждой: прочитай `notes`, текст вакансии и поля скоринга. Перепроверь по `playbooks/scoring.md`:
   стоп-флаги, `company_country`, оценки, `resume_match`, `summary`. Если нужно — открой `real_url` (`npm run fetch-page`).
   Причина в `notes` неясна и сам проблему не находишь — флаг не снимай, допиши в `notes` вопрос `[агент YYYY-MM-DD] …`.
3. Исправь то, что неверно. Не уверен — не меняй, опиши сомнение в `score_reasoning`.
4. Добавь разбор в конец `data/flagged-cases.md` (файл переживёт удаление вакансии чисткой):
   ```
   ## YYYY-MM-DD · <id> · <title> — <company>
   - жалоба: <из notes>
   - вердикт: ошибка скоринга | ошибка данных/парсинга | не подтвердилось
   - что было → что стало: <поля и значения; overall до/после>
   - системный вывод: <правило для scoring.md / prefilter.yaml / провайдера, или «нет»>
   ```
5. Сними флаг: `flagged: false`. Дальше вакансия живёт по общим правилам (без ★/статуса — удалится чисткой).
6. `npm run score && npm run validate`.
7. Повторяющийся системный вывод (≥ 2 случаев в `flagged-cases.md`) — запись `[scoring]`/`[bug]` в `data/insights.md` с конкретной правкой.
8. Отчёт: сколько разобрано, вердикты, что исправлено, системные выводы.

`playbooks/analyze.md` использует `data/flagged-cases.md` как источник типичных ошибок скоринга.
