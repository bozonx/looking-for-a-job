# Playbook: отклик (полуавтомат)

План и обоснования — `dev_docs/apply-plan.md`. **Агент заполняет, пользователь проверяет и нажимает Submit.**
Агент заявки не отправляет никогда: `npm run browser -- click` сам отказывается нажимать «Submit/Send/Отправить»;
флаг `--i-am-human` агенту использовать запрещено.

## Команды

| Фраза | Что |
|---|---|
| «подготовь отклики» [выбранным / по скорингу / `<id>`] | шаги 1–3, без браузера-заполнения (разведка формы — можно) |
| «откликнись» [выбранным / по скорингу / `<id>`] | шаги 1–6; готовый пакет (`application.md` с `state: prepared`) переиспользуется |
| «повтори отклики» | набор `retry`: `needs_attention` + `apply_failed` |
| «продолжи отклики» | прочитать сегодняшний `data/runs/<дата>-apply.md` (раздел «Очередь»), продолжить с текущей вакансии |
| «отправил» / «пропусти» / «не подходит» / «готово» | реакция пользователя по текущей вакансии (шаги 5–6, «Проблемы») |

Режим набора: «откликнись» → `all`, «выбранным» → `selected`, «по скорингу» → `scored`, «повтори» → `retry`.

## Перед началом (один раз за прогон)

1. Прочитай: `profile/about.md`, `profile/answers.md`, `config/cover-letter.md`, `profile/cover-letter.md` (если есть),
   `playbooks/tailor.md` §3, `profile/accounts.md`.
2. Браузер: `npm run browser -- tabs`. Нет ответа → попроси пользователя запустить `npm run browser:start`
   (или запусти сам — окно появится у пользователя) и залогиниться, где нужно.

## Инструменты браузера

`npm run browser -- <команда>` (полный список — `npm run browser -- help`):

- `open <url>` — новая вкладка; `snapshot` — поля (`*` обязательное, ref, тип, метка, значение, варианты), кнопки,
  капча, признак логина; `text` — текст страницы (описание вакансии, сообщения об ошибках).
- `fill <ref> <текст>` (`--type` — посимвольно: автокомплиты, LinkedIn); `select <ref> <вариант>` — и нативный select,
  и кастомный комбобокс/автокомплит (вводит текст, выбирает подходящий вариант); `options <ref> [поиск]` — посмотреть варианты;
  `check <ref> [--off]` — чекбокс и вариант радио (ref варианта); `upload <ref> <файл>`; `click <ref|текст>` — «Apply»,
  «Yes/No»-кнопки, «Accept cookies», «Enter manually».
- `fill-many <plan.json>` — пакетно с паузами `FILL_DELAY_MIN_MS…MAX` (основной способ заполнения): JSON-массив
  `{ "ref", "action": "fill|type|select|check|uncheck|upload", "value" }`. План клади в `data/generated/<id>/fill-plan.json`.
- `screenshot [файл] [--full]`, `wait-for <текст|css>`, `value <ref>`.

Особенности: ref живут до перезагрузки — после навигации/перехода на шаг формы делай `snapshot` заново.
После загрузки файла ATS (Greenhouse) может убрать поле из snapshot и показать имя файла текстом — проверь `text`/скриншот.
«Apply» на странице вакансии обычно открывает форму (Workable, Lever: `…/apply`). Кнопки «Yes/No» в snapshot подписаны вопросом.

## Шаги

### 1. Отбор

1. `npm run apply-set -- <режим>` (или `-- <id …>`). Скрипт уже исключает `possibly_closed`, ⚑, отправленные,
   применяет `APPLY_MAX_PER_RUN` и `LINKEDIN_APPLY_MAX_PER_DAY`.
2. `npm run check-alive -- <id набора …>`, затем снова `apply-set` — закрытые выпадут.
3. `⚠ агрегатор без канала отклика` — найди прямую ссылку или контакт (`npm run resolve-urls -- <id>`, страница вакансии,
   сайт компании), допиши в `apply_channels`/`real_url`, `npm run score`;
   не нашёл → `npm run apply-mark -- <id> attention other "нет канала отклика"`.
   `apply-set` печатает все каналы (`каналы: …`); открывай основной (url), остальные — запасные.
4. Помеченные `?` (только по скорингу, `APPLY_CONFIRM_SCORED`) — покажи списком (компания, роль, overall, площадка)
   и дождись подтверждения. `✓ selected` — без подтверждения.
5. Запиши очередь в лог прогона: `data/runs/<дата>-apply.md`, раздел `## Очередь <ЧЧ:ММ UTC>` — id по порядку, режим.
   По мере работы отмечай текущую вакансию и шаг (`→ <id>: шаг 4`) — это состояние для «продолжи отклики».

### 2. Разведка формы

Для каждой вакансии набора (можно все сразу, до заполнения первой):

1. `open <url из apply-set>`; если формы нет — нажми «Apply»/«Apply now», закрой cookie-баннер; `snapshot`.
2. Логин/регистрация/капча на входе → «Проблемы» ниже. Отклик не через форму — форму не открывать, см. «Отклик сообщением» ниже:
   `apply_method: email | telegram | whatsapp | facebook | dm`.
3. Сопоставь каждое поле с источником (приоритет: `about.md` → `answers.md` → резюме/`facts.md` → генерация).
   Неизвестные вопросы классифицируй (`apply-plan.md` §4.4):
   - **генерируемый** (открытый вопрос об опыте, «почему мы») — ответишь сам на шаге 3;
   - **выводимый** («Years with React») — выведи из `facts.md`, допиши в `answers.md` с пометкой `(выведено, проверить)`;
   - **неизвестный факт/политика** (обязательная зарплата в непредусмотренной валюте, background check, офис раз в месяц…) —
     в список вопросов пользователю.
4. Спецмедиа (видео/аудио под вакансию, тестовое) — в `application.md` → «Мне»; вакансию не останавливает.
5. **Все неизвестные вопросы набора — одним списком в чате**: вакансия, полный текст, тип поля, варианты, обязательность.
   Ответы → в форму и в `answers.md` **обобщённым правилом** (не «для Acme», а «если поле обязательно и в EUR»).
   Пользователь не ответил / «потом» → продолжай с остальными; вопрос — в «Ждут ответа» в `answers.md`.

### 3. Пакет (`data/generated/<id>/`)

1. Резюме: всегда `playbooks/tailor.md` §3 → `resume.<lang>.md` + `tailor.md`, проверка `npm run resume-check -- --file …`,
   PDF — `npm run render-resume -- --file …`. Базовый PDF `data/generated/base/…` — только если пользователь так сказал.
   Вопросы из `resume-check` («нет в facts.md») — в общий список вопросов шага 2.5 и в `profile/questions.md`.
2. Письмо — если нужно (`config/cover-letter.md`, «Когда писать»): `cover-letter.<lang>.md`. Есть текстовое поле —
   вставляй текст; только загрузка файла — сохрани `cover-letter.<lang>.txt` рядом и загрузи его.
3. `application.md` по шаблону `apply-plan.md` §7: front matter (`state: prepared`, `prepared_at`), таблица «Поля»
   (каждое поле формы: обязательность, ответ, источник), «Развёрнутые ответы», «Мне», «Email» (для email-отклика).
   Генерируемые ответы — `apply-plan.md` §4.3: язык формы, прямой ответ первым, 1–2 доказательства из опыта словами вакансии,
   цифры — из `facts.md`, стек и годы — согласованы с отправленным резюме (`resume.<lang>.md`: «Years with Vue» = годы мест, где в нём Vue), под лимит поля; knock-out вопросы — только правда.
4. «подготовь отклики» на этом заканчивается: отчёт — таблица (вакансия, площадка, резюме, письмо, вопросы к пользователю).

### 4. Заполнение

1. Вкладка с формой (`open` заново, если закрыта); `snapshot` — ref обновить.
2. `fill-plan.json` из таблицы «Поля» → `fill-many`. Согласия: privacy/terms/обработка данных — да; рассылки/talent community — нет.
   EEO/демография — «Decline to self-identify». Необязательная зарплата — пусто.
3. `snapshot` ещё раз: все `*` заполнены? Ошибки (`text`)? Что не встало — поправь отдельными командами
   (`select` с другим текстом варианта, `fill --type`).
4. `screenshot data/generated/<id>/filled.png --full`. `npm run apply-mark -- <id> filled`.
5. **Submit не нажимать.** В чат: что заполнено (кратко), что осталось пользователю (капча, медиа, поля без ответа),
   на что посмотреть (сгенерированные ответы, письмо), ссылка на вкладку. Ждать реакции.

#### Отклик сообщением

Email-отклик: ничего не открывать; в `application.md` → «Email»: To (`apply_channels[].value`), Subject (из `note`, иначе
`<Title> — <Имя Фамилия>`), тело (= письмо), путь к PDF. Пользователь отправляет сам.

Telegram / WhatsApp / Facebook / личка (`dm`): ничего не открывать и не писать; в `application.md` → «Сообщение»: куда
(хэндл/ссылка), короткий текст (3–5 предложений на языке вакансии: роль, 1–2 факта под вакансию, ссылка на резюме/LinkedIn),
путь к PDF, требования из `note`. Пользователь отправляет сам. `platform` (hh, habr, djinni…) — откликаешься через браузер
на площадке, как с формой; нет аккаунта → «Проблемы».

### 5. Проверка пользователем

- «отправил» → `snapshot`:
  - если вкладка ещё на форме — сравни значения с `application.md`;
  - если уже произошёл редирект (страница «Thank you» и т.п.) — коротко спроси в чате, правил ли пользователь что-то в ответах или письме.
  - правки пользователя в ответах → `answers.md` (обобщённо); правки письма → `config/cover-letter.md` (общее) или `profile/cover-letter.md` (личное), если повторяются.
  - Раздел «Итог» в `application.md`: что изменил пользователь, что ушло фактически.
  - Если были правки пользователя или ошибки заполнения — запиши в `data/insights.md` с тегом `[apply]` (вакансия, какое поле/ответ, что поправлено).
- «пропусти» [причина] / «не подходит» [причина] — см. шаг 6.

### 6. Фиксация

- «отправил» → `npm run apply-mark -- <id> applied [заметка]`
- «пропусти» → `npm run apply-mark -- <id> skip <причина>` (статус не меняется)
- «не подходит» → `npm run apply-mark -- <id> not-fit <причина>` (в `notes`)
- затем `npm run validate`, следующая вакансия. Между вакансиями на LinkedIn/hh/Djinni/Habr — пауза
  `APPLY_DELAY_MIN_SEC…MAX` (на ATS можно не ждать: пользователь всё равно проверяет форму).

Пока пользователь проверяет одну вакансию, готовь следующие (шаги 2–3).

## Проблемы — не останавливаться, а звать пользователя

Слетел логин, капча на входе, 2FA, «подтвердите email», форма не грузится, непонятное поле:

1. Определи проблему (`snapshot` — «⚠ поле пароля», «⚠ капча»; `url`; `screenshot`).
2. Напиши **конкретное действие**: «Ashby просит войти — залогинься во вкладке <url> и напиши „готово“ (или „пропусти“)».
3. Отметь в логе прогона текущий шаг; жди. Пока ждёшь — готовь пакеты следующих вакансий.
4. «готово» → `snapshot` и продолжай с того же шага. «пропусти» →
   `npm run apply-mark -- <id> attention <login|captcha|special_media|unknown_question|ambiguous|other> "<описание>"`.
5. Техническая ошибка без участия пользователя (браузер упал, 500): одна повторная попытка, затем
   `npm run apply-mark -- <id> failed "<описание>"`.
6. Невидимая reCAPTCHA (`reCAPTCHA (невидимая)`) — не проблема: она сработает на Submit у пользователя.

## Отчёт в конце прогона

В чат и в `data/runs/<дата>-apply.md` (`## <ЧЧ:ММ UTC> — итог`): отправлено / пропущено / needs_attention / apply_failed
(по вакансии одна строка), новые правила в `answers.md`, вопросы в «Ждут ответа», правки в `config/` и `profile/`.
Также допиши в `data/insights.md` с тегом `[apply]` (по одной строке на случай):
- вопросы без ответа, попавшие в «Ждут ответа» или `profile/questions.md` (чтобы видеть повторяющиеся пробелы в фактах);
- ошибки заполнения формы или правки пользователя перед Submit;
- повторяющиеся технические/логин проблемы (`needs_attention` / `apply_failed`) по площадкам.
