# Playbook: обновить заготовки резюме

Фраза: «обнови заготовки резюме [<трек>]». Единственное место, где рыночные данные превращаются в правки резюме.
Пересобирает `profile/resumes/<трек>.md` из банка фактов, конфига треков и рынка вакансий, чтобы заготовки проходили
автоматические фильтры «в среднем по индустрии». PDF (`tailor.md` §1) и резюме под вакансию (`tailor.md` §3) опираются на них.

## Откуда данные

- **рынок** — `npm run insights`: строится из `resume_match` каждой вакансии (`playbooks/scoring.md`), по всем вакансиям
  трека с fit ≥ 50, включая недоступные по локации, с равным весом. Не топ по overall: overall зависит от совпадения
  с резюме, и такой анализ подстраивал бы резюме под то, на что оно уже похоже. Пробелы скрипт считает по **текущему**
  тексту заготовки — после правки отчёт сразу актуален;
- **результат** — раздел «Отклики» в `npm run insights`: конверсия по трекам и версиям заготовок (`outcome`, отмечает пользователь в UI);
- **факты** — `profile/facts.md`, `profile/projects.md`, ответы в `profile/questions.md`; конфиг — `config/resume-tracks.yaml`, `config/tech-dates.yaml`;
- **предпочтения** — срез «Что требуют в выбранных вами» (selected/applied).

Журнал `data/insights.md` для резюме не используется: одна вакансия — не рынок.

## Шаги

1. **Ответы.** Перенеси ответы из `profile/questions.md` в `facts.md` и отметь вопросы `[x]`.
2. **Готовность данных.** `npm run insights` (свежий `data/runs/<дата>-insights.md`). Остановись и предложи сначала
   дозаполнить, если у трека:
   - «Поля v3 заполнены у N из M» с N < 80% M — `npm run pending -- --upgrade`;
   - «⚠ Обязанности вне config/responsibilities.yaml» или в таблице обязанностей всё ×1 — `npm run pending -- --upgrade`;
   - «без рыночных полей: N» — `npm run pending -- --market`.
   Трек «⚠ мало данных» (< 20 вакансий) — правь только написания и порядок навыков, состав не меняй.
   Пользователь может сказать «всё равно обнови» — тогда в отчёте пометь выводы как предварительные.
3. **Разбор по треку** (для каждого из `resume-tracks.yaml` или указанного):
   - **Skills:** навыки из пула `facts.md`, которые встречаются в required/nice_to_have трека, — в порядке частоты,
     сгруппированы (Frontend / State / Testing / Backend / Infra / AI…), самым частым написанием («Как пишут навыки»;
     при заметном разбросе — оба: «Vue.js (Vue 3)»). Навык рынка из «учил»/«само собой» — добавить.
     «ATS: написания» — привести к написанию вакансий. Убрать навыки, которых нет ни в спросе трека, ни в профиле роли. 25–35 позиций.
   - **Пробелы** («не хватает (обязательные)», доля ≥ 10%): опыт есть в фактах — добавить в Skills и пункт опыта;
     нет в фактах — вопрос в `profile/questions.md` (вакансии, доля); ≥ 20% и опыта нет — в отчёте как **кандидат на изучение**
     (сколько вакансий, их overall). Навык из 1–2 вакансий не тащить — это специфика компании.
   - **«Есть в резюме, но вакансия считает минусом»** — повторяется — переформулировать или убрать.
   - **Experience:** места и должности — по `resume-tracks.yaml`; стек — в плейсхолдеры. Пункты закрывают топ обязанностей
     трека (доля ≥ 15% или топ-10 по весу), на JBS — самые частые; формула и лимиты — `tailor.md` §3 п. 4.
     Подтверждение — только из `facts.md`; новый пункт «по мотивам» — сначала в `facts.md` с `~`. Нечем подтвердить — в отчёт.
   - **Summary** — топ-4 навыка спроса, главная обязанность, честно подходящие домены/типы продукта из «Контекст»;
     опыт — 11 лет (сравни с медианой требуемых лет).
   - **Выбранные пользователем** заметно отличаются от рынка трека (домен, стек) — подстрой под выбранное и скажи об этом.
   - **projects** — из `resume-tracks.yaml`; поправь, если рынок трека явно просит другое (и обнови yaml).
   - **soft_skills** — в базовых заготовках по умолчанию берутся первые 7 из `profile/soft-skills.md` (порядок файла = приоритет); если рынок конкретного трека заметно отличается по `Soft / уровень` в `insights`, можно задать `soft_skills` для трека в `resume-tracks.yaml` или скорректировать порядок в `profile/soft-skills.md`.
   - **Треки между собой**: под трек почти нет вакансий или два трека совпадают по спросу — предложи объединить.
4. **Бэкап** старых заготовок в `data/backups/resumes-<дата>/` — по дате бэкапа `insights` разделяет версии заготовок
   в разделе «Отклики». Бэкап обязателен при каждой перезаписи.
5. `npm run resume-check -- --tracks` — исправить все ✗. `npm run render-resume -- --all` — каждый PDF ≤ 2 страниц.
6. Переводы устарели (рендер предупредит) — обнови по `tailor.md` §2 или скажи пользователю.
7. **Отчёт** пользователю (по-русски), по трекам: что добавлено/убрано в Skills и почему (с долями рынка), какие пункты
   поменялись, новые `~` в `facts.md` (просить проверить цифры), новые вопросы в `questions.md`, кандидаты на изучение,
   конверсия прошлой версии заготовок (если ≥ 10 откликов с исходом).
8. Допиши в `data/insights.md`: `- [resume-update] <треки>: <главное изменение>, бэкап data/backups/resumes-<дата>/`.

Заготовки — генерируемые: ручные правки пользователь делает в `facts.md` / `resume-tracks.yaml`.

## Когда запускать

- после «проанализируй журнал», если он это советует (`analyze.md` п. 5);
- после ответов на вопросы в `profile/questions.md`;
- раз в 2–4 недели активного поиска, когда накопилось ≥ 20 новых вакансий трека.
Чаще не нужно: на малой выборке резюме начнёт «дрожать» вслед за случайными вакансиями.
