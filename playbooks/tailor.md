# Playbook: резюме — PDF, переводы, адаптация под вакансию

| Фраза | Что делать |
|---|---|
| «сделай резюме <трек> [на <язык>]», «собери PDF резюме» | §1 — PDF заготовки трека |
| «переведи резюме <трек> на ru/es», «обнови переводы резюме» | §2 — перевод |
| «адаптируй резюме под <id>»; шаг 3 отклика (`playbooks/apply.md`) | §3 — резюме под вакансию |
| «обнови заготовки резюме» | `playbooks/resume-update.md` — пересборка треков из фактов и рынка |

Цель резюме — пройти автоматические фильтры (ATS, ключевые слова рекрутёра) и попасть на собеседование.
Схема: **факты + рынок → заготовки треков** (`resume-update.md`) → **PDF заготовки** (§1, для ручной отправки)
или **заготовка + факты + вакансия → резюме под вакансию** (§3, для отклика).

## Данные

| Файл | Что |
|---|---|
| `profile/facts.md` | банк фактов: пункты по местам работы с ключами обязанностей, плейсхолдерами стека {FE} {STATE} {META} {BE} и каноническими цифрами; пул навыков по уровням; образование |
| `config/resume-tracks.yaml` | по треку: заголовок, проекты, стек и должность на каждом месте; вариации должностей; лимиты длины |
| `config/tech-dates.yaml` | год выхода технологий — проверка анахронизмов |
| `profile/resumes/<трек>.md` | заготовка трека (en): Summary, Skills, Experience. Образование и soft skills сюда не пишутся — их подставляет рендер |
| `profile/resumes/i18n/<трек>.<lang>.md` | переводы заготовок |
| `profile/projects.md` | пет-проекты: описание по умолчанию на en/ru/es + грани `hl[теги]` для описания под вакансию |
| `profile/soft-skills.md` | пул soft skills в порядке приоритета (`## <id>`, `tags`, `en/ru/es`, `proof`): в базовом резюме берутся первые N (7), под вакансию — выбираются релевантные |
| `profile/questions.md` | открытые вопросы пользователю и ответы на них |
| `profile/about.md` | шапка (контакты, локация, языки) — подставляет скрипт |
| вакансия | `resume_match` (required, nice_to_have, keyword_spellings, responsibilities, domain, soft_requirements, in_resume_negative), `red_flags`, текст |

## Граница: что можно писать

Действует только для резюме и ответов в формах; скоринг и данные вакансий — строго по фактам (AGENTS.md).

1. **Из фактов** — без ограничений: переформулировать, переставлять, подставлять стек по `resume-tracks.yaml` или вакансии.
2. **Додумать без вопроса**, если близко к фактам:
   - навыки «само собой разумеющиеся» и «учил, второстепенно» из `facts.md` (Git, REST, unit tests, AWS, Python, Kubernetes…);
   - пункт по обязанности вакансии, если на месте работы есть пункт с тем же или соседним ключом обязанностей
     или та же технология (есть WebSocket → «real-time dashboard»; есть NestJS + PostgreSQL → «designed DB schemas»);
   - новый пункт с цифрой — сначала дописать его в `facts.md` с отметкой `~`, потом использовать: одно достижение — одна цифра везде.
3. **Спросить** (`profile/questions.md`), если вакансия требует навык, технологию или опыт, которых в `facts.md` нет вовсе
   (новый язык, отрасль, роль — например тимлидство, Go, C#, Kafka), и он входит в required или повторяется в нескольких вакансиях.
   Пока ответа нет — не вписывать, вакансию в отчёте пометить «ждёт ответа». Ответ пользователя → факт в `facts.md`, вопрос закрыть.

Жёстко нельзя: менять компании, даты и общий стаж (11 лет, с Aug 2015); технологии новее места работы
(`config/tech-dates.yaml`, ловит `npm run resume-check`); Rust, WebGPU, Godot — только в пет-проектах.

## §1. PDF заготовки трека

`npm run render-resume -- --track <трек> --lang <en|ru|es>` (или `--all`) → `data/generated/base/<Имя>_<трек>_<lang>.pdf`.
Перед этим `npm run resume-check -- --track <трек>`. Нет перевода → §2. Проверь PDF: ≤ 2 страниц, текстовый слой.

## §2. Перевод заготовки

1. Хэш: `npm run render-resume -- --hash <трек>`.
2. `profile/resumes/i18n/<трек>.<lang>.md`: front matter как в оригинале + `lang`, `source_hash`; заголовки секций
   (ru: «О себе», «Навыки», «Опыт»; es: «Resumen», «Habilidades», «Experiencia»); технологии, компании, цифры — как есть;
   даты — месяцы на языке; стиль рынка (ru: «Мигрировал…, сократив…»; es: «Migré…»). Образование не переводить — оно в `facts.md`.
3. `npm run render-resume -- --track <трек> --lang <lang>` — без предупреждения про `source_hash`.

## §3. Резюме под вакансию

Вход: вакансия, `best_resume`. Язык = язык вакансии (en, если неясно). Выход: `data/generated/<id>/resume.<lang>.md`,
front matter: `title`, `projects`, `soft_skills`, `lang`, `vacancy: <id>`.

1. **Основа** — заготовка трека `best_resume` на нужном языке; набор пунктов — из `facts.md`.
2. **Стек по местам.** Фреймворки и стек вакансии — на последних двух местах (JBS, ContentX), самый приоритетный — на JBS.
   Требует несколько (Vue + React, Angular + React) — ставь именно их: главный на JBS, второй на ContentX
   (или оба на JBS, если вакансия хочет оба одновременно). Первые два места — противоположный стек из `resume-tracks.yaml`.
   Проверяй годы: Pinia, Vue 3, Tauri, Signals и т.п. не ставь на места, закончившиеся до их выхода.
3. **Должности.** На JBS — должность как в заголовке вакансии (уровень не ниже Senior, без «Lead/Head», если в фактах
   нет руководства); на ContentX — близкая вариация; старые — из `resume-tracks.yaml`.
4. **Опыт — главное.**
   - Возьми `resume_match.required` и `responsibilities` в порядке важности для вакансии.
   - **JBS** закрывает максимум самых важных: 5–6 пунктов, каждый — одна обязанность или требование вакансии.
   - **ContentX** — следующие по важности (4–5), затем Shutterfly (3–4) и TruckViewer (2–3): по убыванию релевантности.
   - Пункт ищи в `facts.md` по ключу обязанности на этом месте; нет — по соседнему ключу или технологии (§Граница, п. 2).
   - Формула: **глагол + что сделал + на <технология из вакансии, её написанием> + результат в абсолютных величинах**
     (мс, с, КБ, МБ, штуки, часы, пользователи). Проценты — только если абсолютной цифры нет.
   - Формулировки вакансии («own the frontend architecture», «build real-time dashboards») переноси дословно в пункты.
   - Строка «Stack:» — технологии вакансии первыми.
5. **Summary** (2–3 предложения): должность как в вакансии, 11 лет, 3–4 главных required их написанием (`keyword_spellings`),
   домен вакансии, если он есть в опыте.
6. **Skills.** Сначала все required, затем nice_to_have, затем профильное по рынку трека; написание — как в вакансии
   (при разбросе «Vue.js (Vue 3)»). Всё «само собой разумеющееся», что вакансия упоминает (Git, REST, Agile, unit testing),
   — обязательно текстом. 25–35 позиций, группы как в заготовке. `in_resume_negative`, `red_flags` — убрать или приглушить.
7. **Пет-проекты (2–3)** — самые релевантные вакансии по `topics`/`stack`. Описание собери под вакансию из описания
   по умолчанию и 1–2 граней `hl[...]`, совпадающих с требованиями (мобильные → Tauri mobile; графика → WebGPU/PixiJS;
   биллинг/платежи → billing-ai-apps); ≤ 2 строк, на языке резюме:
   `projects: [{id: fastcat, desc: "…"}, tyco]`.
8. **Soft skills (7–10)** — во front matter укажи `soft_skills`:
   - сначала все навыки из `profile/soft-skills.md`, которые совпадают с `resume_match.soft_requirements` и текстом вакансии (по `tags`); при желании формулировку можно уточнить под слова вакансии: `{id: mentoring, text: "…"}`;
   - затем добери самыми приоритетными навыками сверху `profile/soft-skills.md` (в порядке файла), чтобы всего получилось **7–10 пунктов** (с учётом лимита в 2 страницы PDF).
9. **Образование** — не трогать: рендер подставляет его из `facts.md` как есть.
10. **Проверка и рендер.**
   `npm run resume-check -- --file data/generated/<id>/resume.<lang>.md` — исправь все ✗ и проверь ⚠ (включая пропущенные `soft_requirements`); ⚠ про required вне фактов → вопрос.
   `npm run render-resume -- --file data/generated/<id>/resume.<lang>.md` → PDF рядом; ≤ 2 страниц, текстовый слой (`pdftotext`).
11. **Отчёт** `data/generated/<id>/tailor.md` (по-русски): какие обязанности и required каким пунктом закрыты, что додумано
    (новые `~` в `facts.md`), какие проекты и soft skills выбраны и почему, открытые вопросы. Это шпаргалка к собеседованию.
