# Playbook: резюме — PDF, переводы, адаптация под вакансию

Три сценария:

| Фраза | Что делать |
|---|---|
| «сделай резюме <трек> [на <язык>]», «собери PDF резюме» | §1 — базовое резюме трека |
| «переведи резюме <трек> на ru/es», «обнови переводы резюме» | §2 — перевод |
| «адаптируй резюме под <id>»; шаг 3 отклика (этап 3) | §3 — резюме под вакансию |

Улучшение самих треков по рынку — `playbooks/analyze.md` (раздел «Резюме»), правки только с согласия пользователя.
После правки английского трека переводы устаревают — `render-resume` предупредит, обнови по §2.

## Данные

| Файл | Что | Как использовать |
|---|---|---|
| `profile/about.md` | контакты, локация («Локация в резюме»), языки | шапку подставляет скрипт; в тексте резюме не дублировать |
| `profile/resumes/<трек>.md` | «идеальное» резюме трека на английском: front matter (`title`, `projects`) + Summary, Skills, Experience, Education | база |
| `profile/resumes/i18n/<трек>.<lang>.md` | переводы трека (ru, es) | база для ru/es |
| `profile/facts.md` | полный банк правдивых фактов: все пункты опыта, реальный стек, полный пул навыков | можно подтянуть пункт/навык, если его просит вакансия |
| `profile/projects.md` | пул пет-проектов с темами, стеком и описаниями на en/ru/es | выбор 0–2 проектов |
| `profile/soft-skills.md` | soft skills с доказательствами | вплести 1–2 в Summary/пункты, отдельной секцией не выводить |
| вакансия | `resume_match` (required, nice_to_have, ats_keywords_missing, keyword_spellings, responsibilities, domain, soft_requirements, in_resume_negative), `red_flags`, текст | что подсветить и что убрать |

## Граница (жёстко)

Переформулировать, переупорядочивать, опускать и подсвечивать — только то, что есть в треках, `facts.md`,
`projects.md`, `about.md`. Не добавлять технологии, цифры, годы, должности, компании, проекты, которых там нет.
Отсутствующий навык из вакансии не вписывать — он остаётся пробелом (это нормально).
Синоним — можно: если в фактах «GitLab CI», а вакансия пишет «GitLab pipelines» — писать как в вакансии.
Опыт — 11 лет коммерческого (с Aug 2015); Rust/Godot/WebGPU — только пет-проекты, не коммерческий опыт.

## §1. Базовое резюме трека

`npm run render-resume -- --track <трек> --lang <en|ru|es>` (или `--all`). Выход: `data/generated/base/<Имя>_<трек>_<lang>.pdf`.
Нет перевода → сначала §2. Проверь PDF: 1–2 страницы, без пустых секций; покажи путь пользователю.

## §2. Перевод трека

1. Прочитай `profile/resumes/<трек>.md`, получи хэш: `npm run render-resume -- --hash <трек>`.
2. Запиши `profile/resumes/i18n/<трек>.<lang>.md`:
   - front matter: `track`, `title` (переведённый), `projects` (как в оригинале), `lang`, `source_hash: <хэш>`;
   - та же структура; заголовки секций переведены (ru: «О себе», «Навыки», «Опыт», «Образование»;
     es: «Resumen», «Habilidades», «Experiencia», «Educación»);
   - названия технологий, компаний, URL, цифры — как есть; даты — месяцы на языке перевода;
   - стиль — деловой, как пишут резюме на этом рынке (ru: «Мигрировал…, повысив…»; es: «Migré…», 1-е лицо прошедшее);
     без кальки, но и без добавления смысла.
3. Описания пет-проектов переводить не нужно — они в `projects.md` (`ru:` / `es:`); нет нужного — допиши туда.
4. `npm run render-resume -- --track <трек> --lang <lang>` и проверь, что предупреждения про `source_hash` нет.

## §3. Резюме под вакансию

Вход: вакансия (front matter + текст), `best_resume`. Язык = язык вакансии (en, если неясно или иной).

1. **Основа.** Скопируй трек `best_resume` на нужном языке (en — оригинал, ru/es — перевод из i18n; нет перевода —
   переводи сразу адаптированный текст, перевод трека не нужен). Пиши в `data/generated/<id>/resume.<lang>.md`,
   front matter: `title`, `projects`, `lang`, `vacancy: <id>`.
2. **Title.** Должность — ближе к заголовку вакансии, если это честно (`Senior Frontend Engineer` → `Senior Vue.js Developer`
   при вакансии с таким названием). Уровень не завышать и не занижать относительно трека.
3. **Summary (2–3 предложения).** Под домен/тип продукта вакансии, если он есть в опыте; 1–2 главных required-навыка
   её написанием (`keyword_spellings`); 1 soft-skill из `soft_requirements`, если есть доказательство в `soft-skills.md`.
4. **Skills.**
   - порядок: сначала `required`, которые есть, затем `nice_to_have`, которые есть, затем остальное профильное;
   - написание — как в вакансии; при разбросе допустимо «Vue.js (Vue 3)»;
   - навык из `facts.md`, которого нет в треке, но есть в вакансии, — добавить;
   - убрать шум: навыки, не относящиеся к роли и не упомянутые в вакансии (иконка-список из 60 технологий хуже 25 нужных);
     ориентир — 20–30 позиций, группы как в треке; пустые группы удалить;
   - `in_resume_negative` и `red_flags` — убрать или приглушить то, что вакансия считает минусом
     (например, Web3 для консервативного финтеха, «Angular» в резюме на «React-only»).
5. **Experience.**
   - в каждом месте работы — сначала пункты, закрывающие `responsibilities` и `required`; нерелевантные — убрать
     (минимум 2 пункта на место, у последних мест можно 2);
   - пункт из `facts.md` того же места работы, закрывающий требование, — добавить;
   - формула пункта: «глагол + что сделал с помощью <технология из вакансии> + результат/цифра» — только существующие цифры;
   - `ats_keywords_missing`: если смысл уже есть в пункте — переформулировать его словами вакансии;
   - строка «Stack:» — только реальный стек места работы, требуемые технологии первыми.
6. **Пет-проекты (0–2).** Включать, только если проект:
   - закрывает required/nice-to-have, которого нет в коммерческом опыте (WebGPU, Rust, gamedev, LLM-библиотеки), или
   - прямо в домене вакансии (видео/графика → `fastcat`, соцсети/контент → `bloggerdog`/`social-posting`,
     AI-продукт → `ai-kit`/`tyco`, SEO/контент-сайты → `neptu-themes`, бэкенд/микросервисы → `microservices`).
   Иначе `projects: []`. Не брать проекты с темами, противоречащими вакансии. Больше двух — никогда.
7. **Education** — как в треке; формулировку специальности можно сдвинуть ближе к вакансии в пределах `facts.md`
   (например, вариант «Computer Systems UI/UX Design & Engineering» для фронтенда, «Computer Systems & Engineering» для бэкенда).
8. **Рендер.** `npm run render-resume -- --file data/generated/<id>/resume.<lang>.md` → PDF рядом.
   Проверь: 1–2 страницы, текстовый слой (`pdftotext`), все required из вакансии, которые у тебя есть, видны текстом.
9. **Отчёт** (`data/generated/<id>/tailor.md`, по-русски): что поднято/убрано/добавлено из `facts.md`, какие проекты и почему,
   какие required остались пробелом. Это нужно пользователю для собеседования.
