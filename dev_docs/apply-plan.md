# План этапа 3 — отклик

Статус: v2 · 2026-11-16. Уточняет и заменяет `design.md` §5.2 там, где они расходятся.

**Принцип:** агент заполняет всё, что может; капчу, спецмедиа (видео/аудио под вакансию) и кнопку «Submit» —
делаю я. Агент сам заявки **не отправляет** (и не планируется на этом этапе).

## 1. Роли

| Кто | Что делает |
|---|---|
| Я | регистрация и логин на площадках; ответы на неизвестные вопросы; проверка формы; капча, спецмедиа, Submit → «отправил» |
| Агент | отбор, разведка формы, пакет (резюме, письмо, ответы), заполнение полей и загрузка PDF, пополнение `answers.md`, запись результата |
| Скрипты | отбор набора, `check-alive`, PDF резюме, управление браузером (`npm run browser`), запись статуса/лога, валидация |

## 2. Браузер

### Решение: обычный Chromium + свой CLI поверх CDP

- Chromium запускается с отдельным профилем и портом отладки:
  `chromium --user-data-dir=$HOME/.local/share/job-apply-chromium --remote-debugging-port=9222`
  (`npm run browser:start`). Отдельный профиль обязателен — новые Chrome/Chromium не дают отладку на профиле по умолчанию.
  В этом профиле я один раз логинюсь на площадках, пароли — в менеджере паролей браузера, не в файлах проекта.
- Агент управляет им через **скрипт проекта** `scripts/browser.ts` (`playwright-core`, `connectOverCDP` к уже открытому
  браузеру; сам браузер не запускает и не закрывает):
  `npm run browser -- open <url>` · `snapshot` (поля формы с ref, метками, обязательностью, вариантами) ·
  `fill <ref> <text>` · `select` · `check` · `upload <ref> <file>` · `screenshot` · `url` · `wait-for <текст|селектор>`.
- **Почему так:** это обычный bash-вызов — работает с любым агентом (Claude, Codex, …) без настройки MCP для каждого;
  браузер видимый и «мой» (профиль, куки, расширения); не зависит от Orca.
- Альтернативы: браузер Orca (`orca tab/snapshot/fill/upload` — уже умеет всё нужное, но только внутри Orca);
  MCP-сервер (`chrome-devtools-mcp` / `playwright-mcp`) — настраивать отдельно в каждом агенте. Если свой CLI окажется
  хрупким на кастомных селектах — первый fallback: Orca.
- Подключение по CDP следов почти не оставляет (`navigator.webdriver` не выставляется — это не запуск через WebDriver).

## 3. Защита от ботов

Где реально стоит беспокоиться:

| Площадка | Риск | Меры |
|---|---|---|
| LinkedIn | высокий: бан аккаунта за объём и ритм | `LINKEDIN_APPLY_MAX_PER_DAY`, паузы между откликами, приоритет откликов вне LinkedIn (`apply_target`) |
| hh.ru, Djinni, Habr, Indeed | средний/низкий: лимиты частоты | паузы между откликами, без всплесков |
| Workday, сайты за Cloudflare | капча/челлендж | решаю я |
| Greenhouse / Ashby / Lever / Workable | низкий: невидимая reCAPTCHA v3 / спам-фильтр на отправке | отправку делаю я руками — это самый «человеческий» сигнал |

Остальное — не беспокоиться.

Внутри формы: заполнять **поле за полем** короткими случайными паузами 0.3–1.5 с (`FILL_DELAY_MIN_MS`/`MAX`),
а не за один `eval`. Цель не только маскировка: React-формы и автокомплиты (локация, телефон) часто требуют
настоящих событий ввода и времени на подгрузку вариантов. Посимвольный ввод (`TYPE_DELAY_MS`) — только там, где поле
без этого не принимает значение (автокомплит), и на LinkedIn. Многосекундные паузы между полями смысла нет —
детекторы смотрят на объём и ритм откликов за день, а не на скорость заполнения одной формы.

## 4. Данные для ответов

### 4.1. Источники (по приоритету)

1. `profile/about.md` — контакты, локация, гражданство, разрешение на работу, языки, формат занятости.
2. `profile/answers.md` — ответы на типовые вопросы форм (4.2).
3. Резюме под вакансию + `facts.md` / `projects.md` / `soft-skills.md` — всё про опыт.
4. Генерация по вакансии — только открытые вопросы (4.3).

### 4.2. `profile/answers.md`

Разделы по типу вопроса; внутри — канонический вопрос, варианты формулировок, ответ или **правило**:

```markdown
## Работа и документы
### Are you legally authorized to work in <country>?
Варианты: "Do you have the right to work in…", "Work permit…"
Ответ: Аргентина — Yes. Иначе — No; если есть поле про contractor/EOR — "I work as a contractor / via EOR".
### Will you require visa sponsorship?
Ответ: No (удалённо из Аргентины).

## Зарплата
Правило: необязательное поле — не заполнять. Обязательное — спросить меня (ответ — правилом по валюте/формату).

## Опыт по технологиям (годы)
Выведено из facts.md, проверено мной: Vue.js 7 · TypeScript … · Node.js …
Пет-проекты — 0 коммерческих лет.

## Доступность
Notice period: 2 weeks · Готов начать: …

## Демография / EEO (США)
Gender, race, veteran, disability → "Decline to self-identify" / "I don't wish to answer".

## Как узнали о вакансии
`source` вакансии, иначе "Job board".

## Ссылки
LinkedIn, GitHub, Portfolio: …

## Ждут ответа
<!-- агент дописывает; после ответа переносит в нужный раздел -->
```

### 4.3. Генерируемые ответы

- Язык формы/вакансии. Прямой ответ — первым предложением, затем 1–2 доказательства из опыта словами вакансии
  (`keyword_spellings`). Цифры — только существующие. Длина — под лимит поля, без лимита 3–6 предложений.
- Knock-out вопросы (да/нет, годы, право на работу) — только правда, даже если ответ отсеивает.
- «Почему мы» — конкретика из вакансии/сайта компании.

### 4.4. Неизвестные вопросы

| Класс | Пример | Действие |
|---|---|---|
| Генерируемый | «Расскажите о проекте…» | отвечает сам (4.3) |
| Выводимый | «Years with React» | выводит из `facts.md`, пишет в `answers.md` с пометкой `(выведено, проверить)` |
| Неизвестный факт/политика | «Готовы к background check?», обязательная зарплата | спрашивает меня |

Процесс:
1. Разведка формы (§6, шаг 2) собирает неизвестные вопросы **всего набора** — задаю ответы одним списком в начале.
2. Вопрос, всплывший при заполнении: агент заполняет всё остальное, затем спрашивает в чате (полный текст, тип поля,
   варианты). Я отвечаю в чате → агент вписывает в форму **и** сохраняет в `answers.md` обобщённым правилом
   («зарплата, если поле обязательно и в EUR», а не «зарплата для Acme»).
   Либо я заполняю поле сам в браузере → агент читает значение из snapshot и тоже сохраняет.
3. Мне некогда → `needs_attention: unknown_question`, вопрос в «Ждут ответа», следующая вакансия;
   «повтори отклики» пройдёт её заново.

## 5. Сопроводительное письмо

Письмо целиком в пример не нужно — агент копирует структуру, все письма станут одинаковыми. Разделяем:

- **`config/cover-letter.md`** (в git, обезличенное) — общие правила: язык вакансии, 4–6 предложений / ~150 слов,
  без «I am writing to apply», первое предложение — почему эта компания, 1–2 достижения с цифрами из резюме,
  список запрещённых клише («passionate», «rockstar», «I believe I'd be a great fit»), что не писать (переезд,
  гражданство, зарплата, причины ухода), когда писать короткую версию. Туда же переедет
  `profile/cover-letter.example.md`.
- **`profile/cover-letter.md`** (личное) — только то, что про меня: удалёнка и UTC−3, 3–5 фраз «моим голосом»,
  3–5 опорных историй (ссылки на `facts.md`) по типам вакансий. Необязательный файл.

Когда писать: поле есть (даже необязательное) — пишем; нет, но есть «Additional information» — короткая версия;
email-отклик — письмо = тело письма (§6, шаг 4).

Первые 5–10 писем я правлю; повторяющиеся правки агент переносит в `config/cover-letter.md` (общее) или
`profile/cover-letter.md` (личное).

## 6. Процесс

### Команды

| Фраза | Что |
|---|---|
| «подготовь отклики» [выбранным / по скорингу / `<id>`] | шаги 1–3, без заполнения; можно без меня |
| «откликнись» [выбранным / по скорингу / `<id>`] | шаги 1–6; подготовленный пакет переиспользуется |
| «повтори отклики» | `needs_attention` + `apply_failed` |
| «отправил» / «пропусти» / «не подходит» / «готово» | моя реакция по текущей вакансии |

Отбор и лимиты — `design.md` §5.2 (`APPLY_SCORE_THRESHOLD`, `APPLY_MAX_PER_RUN`, `APPLY_CONFIRM_SCORED`,
`LINKEDIN_APPLY_MAX_PER_DAY`).

### Шаги

1. **Отбор.** `check-alive`, без `possibly_closed` и ⚑; агрегатор без `real_url` — найти, не нашли →
   `needs_attention: other`. Отобранные по скорингу — подтвердить.
2. **Разведка формы.** Открыть `apply_target`, snapshot: поля, обязательность, вопросы, файлы, медиа, капча, логин.
   Неизвестные вопросы → 4.4. Спецмедиа → помечается «делаю я», вакансию не останавливает.
3. **Пакет** в `data/generated/<id>/`: `resume.<lang>.md` + PDF (`tailor.md` §3), `cover-letter.<lang>.md`,
   `application.md` (§7).
4. **Заполнение** в видимой вкладке: поля по `application.md`, загрузка PDF, списки, согласия (privacy/terms — да,
   рассылки — нет), скриншот. **Submit не нажимать.** В чате: что заполнено, что осталось мне, на что посмотреть.
   - **Email-отклик:** ничего не открывать; в `application.md` — адрес, тема, тело письма, путь к PDF. Отправляю я.
5. **Проверка мной.** Правлю, капча, медиа, Submit → «отправил». Агент снимает итоговый snapshot, обновляет
   `application.md`; мои правки ответов → `answers.md`, правки письма → §5.
6. **Фиксация.** `status: applied`, `applied_at`, `apply_log` → `data/runs/<дата>-apply.md`; `npm run validate`.
   «пропусти» — без смены статуса, причина в логе; «не подходит» — `notes`. Следующая вакансия.

### Проблемы: не останавливаться, а звать меня

Слетел логин, капча на входе, двухфакторка, «подтвердите email», форма не грузится, непонятное поле:

1. Агент определяет проблему (snapshot/скриншот/URL: страница логина, капча, ошибка).
2. Пишет в чате **конкретное действие**: «Ashby просит войти — залогинься во вкладке <url> и напиши „готово“»
   (или «пропусти»).
3. Ждёт ответа. Состояние прогона (очередь, текущая вакансия, шаг) — в `data/runs/<дата>-apply.md`,
   поэтому продолжение возможно и после перерыва/в новой сессии: «продолжи отклики».
4. «готово» → перепроверяет страницу и продолжает с того же шага; «пропусти» → `needs_attention: login|captcha|other`
   с описанием, следующая вакансия.
5. Техническая ошибка без моего участия (упал браузер, страница 500) — одна повторная попытка, потом `apply_failed`.

Пока я разбираюсь с одной вакансией, агент может заранее готовить пакеты следующих (шаги 2–3 не зависят от меня).

## 7. `data/generated/<id>/application.md`

Черновик для заполнения и запись того, что ушло работодателю (пригодится к интервью):

```markdown
---
vacancy: <id>
company: Acme
title: Senior Vue.js Developer
apply_url: https://jobs.ashbyhq.com/acme/…
apply_method: ats-ashby        # или email
lang: en
resume: Ivan_Kozyrin_vue_en.pdf
cover_letter: cover-letter.en.md
state: prepared                # prepared → filled → submitted | skipped
prepared_at: 2026-11-16T12:00:00Z
submitted_at: null
---

## Поля

| Поле | Обяз. | Ответ | Источник |
|---|---|---|---|
| First name | да | Ivan | about |
| Resume | да | Ivan_Kozyrin_vue_en.pdf | resume |
| Years of experience with Vue | да | 7 | answers |
| Salary expectations | нет | — (пропущено) | answers: правило |

## Развёрнутые ответы

### Why do you want to join Acme?
<текст> · источник: generated

## Мне
- капча; видео 1 мин «о себе» (спецмедиа)

## Email (только для apply_method: email)
To: … · Subject: … · Вложение: Ivan_Kozyrin_vue_en.pdf
<тело письма>

## Итог
Что изменил я при проверке; что ушло фактически.
```

Отдельный статус вакансии «подготовлено» не нужен — достаточно `state` в этом файле.
