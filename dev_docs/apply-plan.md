# План этапа 3 — отклик

Статус: черновик · 2026-11-16. Уточняет и частично заменяет `design.md` §5.2.
Главное отличие от §5.2: агент **не отправляет** заявку сам — он готовит и заполняет форму, а проверяю,
прохожу капчу, записываю медиа и нажимаю «Submit» я. Полная автоотправка — возможно позже, после пилота.

## 1. Роли

| Кто | Что делает |
|---|---|
| Я | регистрируюсь и логинюсь на площадках в браузере Orca; отвечаю на неизвестные вопросы; проверяю заполненную форму; капча, голос/видео, «Submit»; говорю «отправил» / «пропусти» |
| Агент | отбор, подготовка пакета (резюме, письмо, ответы), заполнение полей и загрузка PDF через `orca` (snapshot → fill/select/check/upload), учёт неизвестных вопросов, запись результата в вакансию и лог |
| Скрипты | отбор набора, `check-alive`, PDF резюме (`render-resume`), запись статуса/лога, валидация |

## 2. Этап 0 — аккаунты

Регистрирую я, пароли — в менеджере паролей браузера Orca, **в файлы проекта не попадают**.

- Greenhouse / Lever / Ashby / Workable / SmartRecruiters — обычно форма без аккаунта. Регистрация не нужна
  (у Greenhouse есть необязательный MyGreenhouse — автозаполнение, можно завести).
- Workday — аккаунт на **каждую компанию** отдельно. Регистрируемся по ходу, когда дойдём до вакансии; агент ставит
  `needs_attention: login` и пишет ссылку.
- Площадки с откликом через свой аккаунт: Get on Board, Djinni, Habr Карьера, hh.ru, getmatch, Computrabajo, Bumeran,
  Wellfound, LinkedIn. Регистрируюсь заранее на тех, где реально будут отклики.
- Агрегаторы (vuejobs, himalayas, jobicy, WWR, remotive, working nomads) — сами не принимают отклик, ведут на сайт
  компании/ATS. Перед откликом нужен `real_url` (`npm run resolve-urls` или агент вручную).

Задача: `npm run apply-targets` (новый, маленький) — сколько вакансий в наборе на отклик по каждому `apply_target`
и где нужен аккаунт. По нему решаю, где регистрироваться в первую очередь. Чек-лист аккаунтов — `profile/accounts.md`
(площадка, есть ли аккаунт, заполнен ли профиль на площадке, заметки; без паролей).

Профиль на самих площадках (Djinni, Get on Board, hh, LinkedIn) заполняю я один раз; агент может подготовить тексты
(«о себе», навыки) из резюме — отдельной командой по просьбе.

## 3. Данные для ответов

### 3.1. Откуда агент берёт ответ (по приоритету)

1. `profile/about.md` — контакты, локация, гражданство, разрешение на работу, языки, формат занятости.
2. `profile/answers.md` — ответы на типовые вопросы форм (см. 3.2).
3. Резюме под вакансию + `facts.md` / `projects.md` / `soft-skills.md` — всё, что про опыт.
4. Генерация по вакансии — только открытые вопросы (3.3).

Нет ни в одном источнике и это **факт или политика** (зарплата, виза, дата выхода, «готовы ли к проверке»…) —
не выдумывать, см. 3.4.

### 3.2. `profile/answers.md` — структура

Разделы по типу вопроса, внутри — канонический вопрос, варианты формулировок, ответ, правило:

```markdown
## Работа и документы
### Are you legally authorized to work in <country>?
Варианты: "Do you have the right to work in…", "Work permit…"
Ответ: Аргентина — Yes. Иначе — No; если есть поле «sponsorship / contractor» — "I work as a contractor / via EOR".
### Will you require visa sponsorship?
Ответ: No (работа удалённо из Аргентины).

## Зарплата
### Expected salary
Правило: USD/год — <…>; USD/мес — <…>; RUB/мес — <…>; если поле обязательно и есть диапазон в вакансии — <правило>.

## Опыт по технологиям (годы)
Правило: считать по facts.md (с какого года технология в коммерческом опыте); пет-проекты — 0 коммерческих лет.
Vue.js: 7 · TypeScript: … · Node.js: …

## Доступность
Notice period: 2 weeks · Готов начать: …

## Демография / EEO (США)
Gender, race, veteran, disability → "Decline to self-identify" / "I don't wish to answer".

## Как узнали о вакансии
Правило: источник вакансии (`source`), иначе "Job board".

## Ссылки
LinkedIn, GitHub, Portfolio/Website: …

## Открытые вопросы — тон и заготовки
"Why us", "Tell about a project you're proud of", "Biggest challenge" — опорные истории (ссылки на факты),
генерируются под вакансию.

## Ждут ответа
<!-- агент дописывает сюда; я отвечаю и переношу в раздел выше (или агент переносит после моего ответа в чате) -->
```

Годы опыта по технологиям лучше один раз посчитать агентом по `facts.md` и я проверю — это самый частый вопрос ATS.

### 3.3. Генерируемые ответы

- Язык — язык формы/вакансии.
- Короткий фактический ответ на прямой вопрос первым предложением, затем 1–2 доказательства из опыта
  с ключевыми словами вакансии в её написании (`keyword_spellings`). Цифры — только существующие.
- Длина — под поле: если есть лимит символов — уложиться; без лимита — 3–6 предложений.
- Knock-out вопросы (да/нет, годы, разрешение на работу) — **только правда**, даже если ответ отсеивает.
  Лучше отсев, чем отказ после интервью.
- «Почему мы» — конкретика из текста вакансии/сайта компании, не общие слова.

### 3.4. Неизвестные вопросы — как наполняем файл по ходу

Три класса вопросов:

| Класс | Пример | Что делает агент |
|---|---|---|
| Генерируемый | «Расскажите о проекте…» | отвечает сам (3.3) |
| Выводимый | «Years with React» | выводит из `facts.md`, записывает вывод в `answers.md` с пометкой `(выведено, проверить)` |
| Неизвестный факт/политика | «Ожидаемая зарплата в EUR», «Готовы ли к background check» | не заполняет |

Неизвестный обязательный вопрос:

1. Агент дописывает его в `answers.md` → «Ждут ответа»: полный текст, тип поля (текст/да-нет/список вариантов),
   варианты, вакансия `<id>`.
2. Если я рядом (интерактивная сессия) — спрашивает сразу в чате; мой ответ агент сразу переносит в нужный раздел
   как правило (обобщая: не «зарплата для Acme», а «зарплата, если валюта EUR»).
3. Если не ответил — вакансия `needs_attention: unknown_question`, переходим к следующей.
   «повтори отклики» после пополнения `answers.md` проходит её заново.

Для пакетного режима: подготовка (§5, шаг 2) собирает **все** неизвестные вопросы набора в один список в начале,
чтобы ответить разом, а не дёргаться на каждой вакансии. Вопросы формы видны только при её открытии — значит,
«разведка» форм (открыть, снять snapshot, не заполнять) идёт в шаге подготовки.

## 4. Сопроводительное письмо

**Пример письма целиком не нужен** — агент будет копировать его структуру и фразы, и все письма станут одинаковыми.
Нужно другое, в `profile/cover-letter.md`:

- **Правила** (как в `cover-letter.example.md`): язык вакансии, 4–6 предложений / до ~150 слов, без «I am writing to apply»,
  первое предложение — почему эта компания, 1–2 достижения с цифрами, удалёнка и UTC−3.
- **Голос** — 3–5 примеров фраз, как я говорю о себе, и список запрещённых клише («passionate», «rockstar», «synergy»,
  «I believe I would be a great fit»). Это задаёт тон без шаблона.
- **Опорные истории** — 3–5 ссылок на факты из `facts.md`, которые хочу продвигать (по типам вакансий: frontend, fullstack,
  AI). Агент выбирает 1–2 под вакансию.
- **Что не писать** — переезд, гражданство, зарплата (если не спрашивают), причины ухода.

Когда письмо писать:
- поле есть (обязательное или нет) — пишем; необязательное поле с письмом заметно повышает шанс прочтения рекрутером;
- поля нет, но есть «Additional information» — короткая версия (2–3 предложения);
- отклик по email — письмо = тело письма.

Первые 5–10 писем я читаю и правлю; правки, которые повторяются, агент переносит в правила `cover-letter.md`
(так файл и докручивается — это лучше, чем писать пример заранее).

## 5. Процесс отклика

### Команды

| Фраза | Что |
|---|---|
| «подготовь отклики» [выбранным / по скорингу / `<id>`] | шаги 1–3 без браузерного заполнения; можно делать без меня |
| «откликнись» [выбранным / по скорингу / `<id>`] | шаги 1–6; если пакет уже подготовлен — сразу к 4 |
| «повтори отклики» | `needs_attention` + `apply_failed` после пополнения `answers.md` |
| «отправил» / «пропусти» / «не подходит» | моя реакция по текущей вакансии в шаге 5 |

Отбор наборов и лимиты — как в `design.md` §5.2 (`APPLY_SCORE_THRESHOLD`, `APPLY_MAX_PER_RUN`, `APPLY_CONFIRM_SCORED`,
`LINKEDIN_APPLY_MAX_PER_DAY`). Паузы `APPLY_DELAY_*` при ручной отправке не нужны — темп задаю я.

### Шаги

1. **Отбор.** `check-alive` по набору, без `possibly_closed` и ⚑; нет `real_url` у агрегатора — найти; не нашли —
   `needs_attention: other`. Показать список, подтвердить отобранные по скорингу.
2. **Разведка формы.** Открыть `apply_target`, snapshot: список полей, обязательность, вопросы, загрузка файлов, медиа,
   капча, нужен ли логин. Неизвестные вопросы → 3.4. Нужен логин без аккаунта → `needs_attention: login`.
   Нестандартное медиа → отметить «делаю я», вакансию не останавливает.
3. **Пакет** в `data/generated/<id>/`:
   - `resume.<lang>.md` + PDF (`playbooks/tailor.md` §3);
   - `cover-letter.<lang>.md`;
   - `application.md` — все поля формы → ответ → источник (`about` / `answers` / `generated` / `derived` / `me`).
     Это и черновик для заполнения, и запись того, что ушло работодателю (пригодится к интервью).
4. **Заполнение** в видимой вкладке Orca: поля по `application.md`, загрузка PDF (`orca upload`), выбор в списках,
   чекбоксы согласий (privacy/terms — да; маркетинговые рассылки — нет). Скриншот заполненной формы.
   **Не нажимать Submit.** Сообщить в чате: что заполнено, что осталось мне (капча, медиа, поля `me`), на что обратить внимание.
5. **Проверка мной.** Правлю, капча, медиа, Submit → «отправил». Если правил ответы — агент снимает snapshot
   и записывает итог в `application.md` (и повторяющиеся правки — в `answers.md` / `cover-letter.md`).
6. **Фиксация.** `status: applied`, `applied_at`, `apply_log` → `data/runs/<дата>-apply.md`; «пропусти» —
   статус не меняется, причина в заметке лога; «не подходит» — `notes` + решение, как в UI. `npm run validate`.
   Дальше — следующая вакансия.

Капча/логин/сбой посреди заполнения — я разбираюсь на месте или говорю «пропусти» → `needs_attention` / `apply_failed`.

## 6. Что сделать (порядок)

1. `profile/answers.md` и `profile/cover-letter.md` по структуре §3.2 и §4; агент предзаполняет годы по технологиям
   и истории из `facts.md`, я дописываю зарплату, визы, доступность (сейчас `…` в `about.md`).
2. `profile/accounts.md` + `npm run apply-targets`; регистрируюсь на нужных площадках.
3. `playbooks/apply.md` по §5; маршруты в `AGENTS.md`.
4. Скрипты: `apply-set` (отбор набора с лимитами) и `apply-mark` (applied / attention / failed + лог) —
   рутина вне агента; zod-схема для новых полей при необходимости.
5. **Пилот** на 3–5 вакансиях Greenhouse/Ashby (без логина, частые): проверить `orca fill`/`select`/`upload` на реальных
   формах (кастомные React-селекты, автокомплит локации, file input), качество писем и ответов.
6. По итогам пилота — правки playbook, затем площадки с логином (Get on Board, Djinni), потом Workday и LinkedIn.
7. Обновить `design.md` §5.2 под этот план.
