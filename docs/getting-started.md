# Старт с нуля

Что сделать один раз, прежде чем говорить агенту «собери».

## 1. Окружение

- **Node.js ≥ 23.6** — скрипты на TypeScript запускаются нативно, без сборки. Проверка: `node -v`.
- **Агент** — Claude Code, Codex или любой другой, умеющий читать `AGENTS.md`. Запускается из корня репозитория.
- **Chromium/Chrome** — нужен для откликов и PDF резюме. Для откликов запустите `npm run browser:start` (CDP :9222); сбор открытых API и лент работает без браузера.

```bash
npm install
cp .env.example .env      # необязательно: у всех параметров есть значения по умолчанию
```

Проверка, что всё живо:

```bash
npm run typecheck
npm run validate          # на пустой data/ напишет «Checked 0»
```

## 2. Личные данные — `profile/`

Папка в `.gitignore` целиком, в git лежат только шаблоны `*.example.md`. Скопируйте каждый шаблон без `.example` и заполните:

```bash
cd profile
cp about.example.md about.md
cp answers.example.md answers.md
cp cover-letter.example.md cover-letter.md   # необязательно
cp accounts.example.md accounts.md
cp resumes/vue.example.md resumes/vue.md
cp projects.example.md projects.md
cp facts.example.md facts.md
cp soft-skills.example.md soft-skills.md
cp questions.example.md questions.md
```

| Файл | Что вписать | Нужен уже сейчас? |
|---|---|---|
| `about.md` | контакты, «Локация в резюме» (строка в шапке PDF), город и часовой пояс, гражданство, ВНЖ/визы, готовность к переезду, зарплатные ожидания, форма занятости, языки с уровнями | да — агент учитывает при скоринге (регион, визы, языки) |
| `resumes/<трек>.md` | заготовки резюме по направлениям (`vue`, `react`, `angular`, `fullstack`, `ai-engineer`, `automation`): Summary, Skills, Experience на английском, без контактов, проектов, образования и soft skills (их подставляет рендер). Собирает агент: «обнови заготовки резюме» (`playbooks/resume-update.md`) из `facts.md`, `config/resume-tracks.yaml` и рынка | желательно — на них опирается `fit` и `best_resume` |
| `facts.md` | банк фактов: пункты опыта с ключами обязанностей и цифрами, пул навыков по уровням, образование. Правите вы; агент дописывает черновики с `~` | для всех резюме |
| `projects.md` | пет-проекты: темы, описания на en/ru/es и грани `hl[...]` для описания под вакансию | для резюме (2–3 по теме) |
| `soft-skills.md` | пул soft skills в порядке приоритета (`en/ru/es`, `tags`, `proof`) — топ-7 в базовом резюме, 7–10 под вакансию | для резюме |
| `questions.md` | вопросы агента о навыках, которых нет в `facts.md`; ответы пишете вы | для резюме под вакансию |
| `answers.md` | ответы на типовые вопросы форм (опыт по годам, notice period, разрешение на работу…). Агент будет дописывать новые вопросы, ответы правите вы | для этапа 3 (отклик) |
| `cover-letter.md` | личное для писем: формат работы, фразы «своим голосом», опорные истории. Общие правила — `config/cover-letter.md` | необязательно, этап 3 |
| `accounts.md` | на каких площадках есть аккаунт (без паролей) | для этапа 3 |
| `media/` | заготовленные видео-/аудио-визитки | для этапа 3 |

Резюме по направлениям, которых у вас нет, можно не создавать — но тогда уберите трек из рассмотрения (вес 0 в `config/weights.yaml → fit_tracks`).

## 3. Предпочтения — `config/`

Эти файлы обезличены и лежат в git. Значения по умолчанию отражают исходные предпочтения автора — пройдитесь и поправьте под себя.

| Файл | Что проверить |
|---|---|
| `config/preferences.md` | текстом: что для вас важно, какие стоп-факторы. Это читает агент |
| `config/weights.yaml` | те же предпочтения числами — веса критериев, веса треков, стоп-флаги. Это читает `npm run score` |
| `config/regions.yaml` | группы стран работодателя: оценка 0–100 и список ISO-кодов |
| `config/prefilter.yaml` | слова в заголовке, которые сразу отсеивают / пропускают вакансию (без LLM) |
| `config/apply-priority.yaml` | порядок мест отклика (сайт компании, ATS, каналы, площадки) при нескольких вариантах |
| `config/sources.md` | список площадок и их статус (✅ = собирается) |

Важно: `preferences.md` и `weights.yaml` должны говорить одно и то же. Поменяли смысл в одном — поправьте второй. Подробно о том, как веса превращаются в балл, — [how-it-works.md](how-it-works.md#скоринг).

Стоп-факторы (`office_outside_ar`, `location_restricted`, `nationality_excluded`, `ru_corporate`) и список регионов зашиты под конкретную ситуацию (живу в Аргентине). Если ваша другая — поменяйте описание в `preferences.md`, `playbooks/scoring.md`, `dev_docs/design.md §8.1`; для нового значения флага или региона нужно также расширить enum в `scripts/lib/enums.ts`.

## 4. Первый сбор

Пробный прогон без записи:

```bash
npm run collect -- --dry-run
```

Покажет, сколько вакансий в ленте, сколько отсеет предфильтр и сколько было бы сохранено. Если отсеивается слишком много/мало — правьте `config/prefilter.yaml`.

Дальше — скажите агенту **«собери»**. Он выполнит `playbooks/collect.md`: запустит скрипт сбора, отскорит новые вакансии, посчитает итог, проверит схему, допишет журнал наблюдений и выдаст топ.

Для первого раза удобно ограничить объём: `npm run collect -- --limit 5`, затем попросить агента «отскорь pending».

## 5. Просмотр

```bash
npm run dev     # http://localhost:3000
```

Отмечайте интересное (`a`), снимайте выбор (`u`), ставьте звёзды (`s`). См. [running.md](running.md#ui).

## 6. Через несколько дней

- Прочитайте `data/insights.md` — журнал наблюдений агента. Переносите выводы в `preferences.md`/`weights.yaml`, `prefilter.yaml`, `answers.md`, резюме. Подробнее — [how-it-works.md](how-it-works.md#журнал-наблюдений).
- Поменяли веса → `npm run rescore` или кнопка rescore в UI.

## Чек-лист

- [ ] резюме в `profile/resumes/` по нужным трекам

- [ ] `config/regions.yaml`, `config/prefilter.yaml` проверены
- [ ] `npm run collect -- --dry-run` даёт разумную картину
- [ ] агенту сказано «собери», `npm run validate` без ошибок
- [ ] `npm run dev` открывается
