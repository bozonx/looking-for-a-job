# Переменные окружения

Файл `.env` в корне (шаблон — `.env.example`). Не обязателен: у каждого параметра есть значение по умолчанию. Скрипты подхватывают его через `node --env-file-if-exists=.env`.

В `.env` — только числовые лимиты и флаги. **Персональные данные сюда не кладутся** — они в `profile/` (markdown удобнее для агента).

## Сбор (используются сейчас)

Читаются в `scripts/lib/env.ts`. Нечисловое значение → скрипт падает с ошибкой.

Лента обходится от новых к старым; обход останавливается при **первом** сработавшем условии.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `COLLECT_MAX_PAGES` | `5` | не более N страниц пагинации. **RemoteOK:** не применяется — API отдаёт ~100 последних вакансий одной страницей |
| `COLLECT_MAX_AGE_DAYS` | `30` | предел окна сбора. Окно у каждого источника своё: с прошлого **полного** сбора этого источника минус 2 дня запаса (`data/state/lastrun.json`), но не дальше N дней и не дальше `freshness_days` источника; первый сбор — столько же. Пропуски (отпуск, праздники) догоняются сами. Вакансии вне окна (по дате публикации) пропускаются; без даты — не проверяются. Snapshot-источники (`ats`, `yc`, `landingjobs`) окна не имеют |
| `COLLECT_STOP_ON_SEEN` | `5` | только для источников с пагинацией: встретили N **подряд** известных **или** слишком старых вакансий → текущая страница дочитывается до конца, следующие не грузятся. Источники без пагинации всегда просматриваются целиком (список уже скачан, проверка бесплатна). После оборванного сбора известные не останавливают — только вышедшие из окна по дате. Известные = сохранённые в `data/vacancies/` + все обработанные ранее, включая отсеянные и удалённые (`data/state/seen-<источник>.json`, хранятся ≥ 90 дней). Счётчик сбрасывается на каждой новой — одна закреплённая/промо-вакансия наверху ленты сбор не остановит |
| `COLLECT_MAX_NEW` | `300` | страховка: не больше N новых вакансий с источника за запуск. В норме не срабатывает; сработал — в логе «⚠ Предупреждения», проверьте фильтры источника |

Лента дочитана до конца, а известных или старых вакансий в ней нет ни одной → в логе «⚠ возможен пропуск»: между сборами вышло больше, чем отдаёт площадка (лента фиксированного размера). Решение — собирать этот источник чаще или сузить его фильтр. Первый сбор и snapshot-источники не проверяются.

Пустая первая страница списка считается ошибкой источника (капча, логин, сменилась вёрстка), а не «нет новых».

Сбор, оборвавшийся на ошибке, `--limit`, `COLLECT_MAX_NEW` или `COLLECT_MAX_PAGES`, а также сбор, у которого не загрузилась часть лент/категорий или упало построение записи вакансии, не сдвигает окно — следующий запуск доберёт хвост (без остановки на известных). Вакансия, на которой построение записи падает 3 сбора подряд (например, 404), считается известной и больше не пробуется (`data/state/seen-<источник>.json`, «errN»).

Свежесть — не переменная окружения, а `freshness_days` в `config/sources.yaml` (по источникам). Она действует дважды: ограничивает окно сбора (вакансии старше срока не загружаются вовсе) и очередь скоринга — `npm run pending` не отдаёт агенту собранные ранее, но уже постаревшие вакансии (файлы остаются, `--stale` берёт их).

## Скоринг (агент)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SCORE_MAX_PER_RUN` | `50` | сколько вакансий агент скорит за один «собери» (`npm run pending` отдаёт столько, свежие первыми). Остальные остаются со `scores: null` и берутся следующим запуском. Это главный регулятор расхода токенов: сбор скриптом бесплатен, дорог только скоринг |

Как подбирать:
- Собираете редко — окно считается от прошлого сбора, но не глубже `freshness_days` источника: после перерыва длиннее этого срока более старые вакансии не соберутся (откликаться на них уже поздно). Нужны все — временно поднимите `freshness_days` или поставьте `null`. Собранные, но не отскоренные до перерыва — `npm run pending -- --stale`.
- Источники с короткой лентой (NoDesk ~10, Working Nomads ~30–50 последних) при редком сборе теряют вакансии независимо от окна.
- Агент тратит токены на «поздние» вакансии — уменьшите `freshness_days` источника в `config/sources.yaml`.
- Площадка часто поднимает старые вакансии наверх — увеличьте `COLLECT_STOP_ON_SEEN`.
- Для LinkedIn держите `COLLECT_MAX_PAGES` маленьким — объём чтения тоже риск блокировки.

## Отклик (этап 3)

Читаются в `scripts/lib/env.ts`; используются `apply-set`, `browser` и `playbooks/apply.md`. Детали — `dev_docs/apply-plan.md`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `APPLY_SCORE_THRESHOLD` | `80` | «откликнись» без уточнения берёт `selected` ∪ (`new` и `overall ≥` порога) |
| `APPLY_MAX_PER_RUN` | `15` | максимум откликов за один запуск |
| `APPLY_CONFIRM_SCORED` | `true` | вакансии, попавшие в список только по порогу (не выбранные вами), показать и ждать подтверждения. Выбранные вами (`selected`) — без подтверждения |
| `LINKEDIN_APPLY_MAX_PER_DAY` | `5` | лимит автоматических откликов агента через LinkedIn за сутки (по `applied_at`; ручные отклики не считаются). Первую неделю можно держать 3 |
| `APPLY_DELAY_MIN_SEC` | `60` | минимальная случайная пауза между вакансиями |
| `APPLY_DELAY_MAX_SEC` | `240` | максимальная пауза |
| `TYPE_DELAY_MS` | `40` | задержка между символами при посимвольном вводе (`browser fill --type`, `select` в автокомплите) — только там, где поле иначе не принимает значение, и на LinkedIn |
| `FILL_DELAY_MIN_MS` | `300` | минимальная случайная пауза между полями формы (`browser fill-many`) |
| `FILL_DELAY_MAX_MS` | `1500` | максимальная пауза между полями |
| `BROWSER_CDP_URL` | `http://127.0.0.1:9222` | адрес отладки Chromium (`npm run browser:start`); порт берётся отсюда |
| `CHROMIUM_BIN` | — | путь к Chromium/Chrome, если не найден в `/usr/bin` |

## Добавление новой переменной

1. Добавить в `.env.example` с комментарием.
2. Прочитать в `scripts/lib/env.ts` через `num(name, default)` (или аналог), чтобы было значение по умолчанию и проверка.
3. Описать здесь и в `dev_docs/design.md §9`.
