# Запуск

Все команды — из корня репозитория. Скрипты читают `.env`, если он есть (`node --env-file-if-exists=.env`).

## Через агента (основной способ)

| Сказать агенту | Что произойдёт |
|---|---|
| «собери», «собери вакансии» | `playbooks/collect.md`: сбор со всех источников со статусом ✅ → скоринг новых → `score` → `validate` → запись в `data/insights.md` → отчёт с топ-5 |
| «открой UI», «покажи вакансии» | `npm run dev` |
| «откликнись …» | этап 3 ещё не реализован — агент так и скажет |

## Типичный день

1. Агенту: «собери».
2. `npm run dev` → вкладка «Новые», разбираете: `a` — выбрать, `x` — отклонить.
3. Смотрите вкладку «Требуют внимания».
4. (Позже, этап 3) агенту: «откликнись».

Сбор инкрементален: можно запускать хоть несколько раз в день — известные вакансии не сохраняются повторно, а постраничные ленты перестают грузить страницы после `COLLECT_STOP_ON_SEEN` известных подряд.

## Команды

| Команда | Что делает |
|---|---|
| `npm run collect` | Фаза A сбора со всех источников (`-- <id>` — с выбранных; `collect:remoteok` — псевдоним): лента → лимиты → предфильтр → дедупликация → новые файлы со `scores: null` → лог в `data/runs/` |
| `npm run pending` | вакансии, ждущие скоринга агентом (`scores: null` и `status: new`), кроме несвежих (`freshness_days` источника) |
| `npm run score` | `overall` и производные поля для отскоренных, у которых `overall` ещё не посчитан |
| `npm run rescore` | то же для **всех** вакансий (`score --all`) — после правки весов/регионов/приоритетов |
| `npm run validate` | zod-проверка front matter; код выхода 1 при ошибках |
| `npm run dedupe` | диагностика индекса дублей |
| `npm run channels -- [--force] [--dry-run] [id …]` | каналы отклика (`apply_channels`: ATS, форма, email, Telegram, WhatsApp, Facebook, личка) из ссылок и текста, пересчёт `apply_method`/`apply_target` |
| `npm run fetch-page -- <url\|file.html> [--out f.md]` | страница → markdown (для HTML-площадок и поиска `real_url`) |
| `npm run cleanup` | удаление старых вакансий: `--older-than 30d` (по умолчанию `CLEANUP_DEFAULT_DAYS`), `--status rejected,applied`, `--dry-run`; со звездой не трогает |
| `npm run render-resume -- --track vue [--lang en\|ru\|es]` | PDF резюме трека в `data/generated/base/` (шапка из `about.md`, проекты из `projects.md`). `--all` — все треки × готовые переводы; `--file <md>` — адаптированное под вакансию; `--projects a,b` — свой набор проектов; `--html` — только HTML; фото `profile/photo.jpg` — только в ru (`--photo` / `--no-photo`). Переводы и адаптацию делает агент — `playbooks/tailor.md` |
| `npm run dev` | UI на http://localhost:3000 |
| `npm run ui:build` | production-сборка UI в `app/.output/` |
| `npm run typecheck` | проверка типов скриптов и `.ts`-кода UI (`.vue` не проверяются) |

### Флаги

**`collect`**

| Флаг | Смысл |
|---|---|
| `--dry-run` | ничего не записывать (ни вакансии, ни лог, ни `seen`) — только показать |
| `--limit N` | сохранить не более N новых вакансий (на каждый источник) |
| `--file path.json` | взять ленту из файла вместо сети (отладка; только с одним источником) |

Код выхода: 0 — ок, 1 — у какого-то источника не загрузился список, 2 — неверные аргументы.

Аргументы npm передаются после `--`: `npm run collect -- remoteok --dry-run --limit 3`.

**`pending`** — `--paths`: только пути к файлам; `--stale`: включить несвежие (старше `freshness_days`); `--all`: без лимита и со несвежими.

**`score` / `validate`** — можно передать id или пути: `npm run score -- remoteok-1137713`. С явным списком `score` пересчитывает указанные, даже если `overall` уже есть.

**`dedupe`**

| Вызов | Смысл |
|---|---|
| `npm run dedupe -- --index` | статистика индекса (по умолчанию) |
| `npm run dedupe -- --check "Acme" "Senior Vue Developer" [url…]` | есть ли такая вакансия среди сохранённых |
| `npm run dedupe -- --groups` | вероятные дубли среди уже сохранённых (одинаковые компания+должность) |

## Ручной сбор без агента

Можно пройти конвейер руками — полезно для отладки:

```bash
npm run collect                   # фаза A
npm run pending                   # что нужно отскорить
# … заполнить поля по playbooks/scoring.md в каждом файле …
npm run score && npm run validate
```

## UI

`npm run dev` → http://localhost:3000. Сервер читает все `data/vacancies/**/*.md` в память и следит за изменениями; браузер раз в 5 с обновляет список, пока вкладка видима. Поэтому агент и UI могут работать одновременно.

**Вкладки** — сохранённые наборы фильтров и сортировки. Все вкладки устроены одинаково: любое изменение фильтра сразу запоминается для текущей вкладки (localStorage браузера).
Встроенные: «Все» (все открытые), «Новые» (период = последний сбор), «Выбранные», «⚑ Проблемные», «Закрытые». `+` — новая вкладка из текущих фильтров, двойной клик — переименовать, `×` — удалить (кроме встроенных). Если фильтры отличаются от исходных, появляются «↺ сброс» (вернуть) и «✓ закрепить» (сделать текущие исходными).

**Фильтры:** статус (мультивыбор, значения объединяются через ИЛИ): без решения, выбрана, внимание (`needs_attention`), отклик, ошибка (`apply_failed`), ⚑ проблемные, закрытые. Закрытые (`possibly_closed`) видны только если выбрано «закрытые»; если выбрано только оно — показываются только закрытые. Ещё: overall ≥, профиль, источник, регион, язык, период (всё время / последний сбор / за N дней).

**Поиск** (`/`) — быстрый, по названию/компании/локации внутри текущей вкладки, не сохраняется. Если есть совпадения вне вкладки, показывается ссылка «искать во „Все“».

**Сортировка** — клик по заголовку колонки (повторный клик меняет направление); Shift+клик добавляет следующий ключ (номер рядом со стрелкой). R/S/C/O/L — сортировка по remote/startup/corporate/outsource/legitimacy. ★ всегда сверху.

**Горячие клавиши:**

| Клавиша | Действие |
|---|---|
| `a` | выбрать → `selected` |
| `u` | снять выбор |
| `s` | звезда |
| `f` | ⚑ проблемная |
| `j` / `↓`, `k` / `↑` | следующая / предыдущая |
| `/` | поиск |

UI пишет в файл только `status` (`null`/`selected`), `starred`, `flagged`, `notes`. Перед записью файл перечитывается с диска, запись атомарная — правки агента не затираются. Кнопка **⟳ rescore** — то же, что `npm run rescore`; **✓ живость** — `npm run check-alive` в фоне (Shift+клик — перепроверить и проверенные сегодня). Файлы, которые не удалось разобрать, показываются списком ошибок.

## Где смотреть результаты

| Путь | Что |
|---|---|
| `data/vacancies/ГГГГ/ММ/<дата>-<источник>-<компания>-<должность>.md` | вакансии |
| `data/runs/<дата>-collect.md` | лог сбора: сколько в ленте / просмотрено / отсеяно (с причинами) / известных / дублей / сохранено, причина остановки |
| `data/state/seen-<источник>.json` | id, отсеянные предфильтром (60 дней) |
| `data/insights.md` | журнал наблюдений агента |

## Если что-то не так

- `validate` ругается `scores.overall: not computed` → не запущен `npm run score`.
- Вакансия пропала из UI → скорее всего ошибка разбора YAML; она в списке ошибок в UI и в `npm run validate`.
- Сбор ничего не находит → посмотрите причину остановки в `data/runs/`; возможно, всё уже известно или вне окна (строка «окно» в логе).
- Нужно «забыть» отсеянное предфильтром (например, после правки `prefilter.yaml`) → удалите `data/state/seen-<источник>.json`.
