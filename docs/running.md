# Запуск

Все команды — из корня репозитория. Скрипты читают `.env`, если он есть (`node --env-file-if-exists=.env`).

## Через агента (основной способ)

| Сказать агенту | Что произойдёт |
|---|---|
| «собери», «собери вакансии» | `playbooks/collect.md`: сбор со всех источников со статусом ✅ → скоринг новых → `score` → `validate` → запись в `data/insights.md` → отчёт с топ-5 |
| «открой UI», «покажи вакансии» | `npm run dev` |
| «откликнись …» | подготовка резюме и заполнение формы по `playbooks/apply.md`; Submit нажимает пользователь |

## Типичный день

1. Агенту: «собери».
2. `npm run dev` → вкладка «Новые»: `a` — выбрать, `u` — снять выбор.
3. Смотрите вкладку «Внимание».
4. Агенту: «откликнись выбранным». Проверяете заполненную форму и нажимаете Submit.

Сбор инкрементален: можно запускать хоть несколько раз в день — известные вакансии не сохраняются повторно, а постраничные ленты перестают грузить страницы после `COLLECT_STOP_ON_SEEN` известных подряд.

## Команды

| Команда | Что делает |
|---|---|
| `npm run collect` | Фаза A сбора со всех источников (`-- <id>` — с выбранных; `collect:remoteok` — псевдоним): лента → лимиты → предфильтр → дедупликация → новые файлы со `scores: null` → лог в `data/runs/` |
| `npm run pending` | вакансии, ждущие скоринга агентом (`scores: null`), кроме отсеянных предфильтром, закрытых, `hire_from_ar: no`, со стоп-флагами и несвежих (`freshness_days` источника); статус решения не ограничивает очередь |
| `npm run score` | `overall` и производные поля для отскоренных, у которых `overall` ещё не посчитан |
| `npm run rescore` | то же для **всех** вакансий (`score --all`) — после правки весов/регионов/приоритетов |
| `npm run validate` | zod-проверка front matter; код выхода 1 при ошибках |
| `npm run dedupe` | диагностика индекса дублей |
| `npm run channels -- [--force] [--dry-run] [id …]` | каналы отклика (`apply_channels`: ATS, форма, email, Telegram, WhatsApp, Facebook, личка) из ссылок и текста, пересчёт `apply_method`/`apply_target` |
| `npm run fetch-page -- <url\|file.html> [--out f.md]` | страница → markdown (для HTML-площадок и поиска `real_url`) |
| `npm run cleanup` | удаление старых вакансий: `--older-than 30d` (по умолчанию `CLEANUP_DEFAULT_DAYS`), `--dry-run`; отмеченные (статус, ★, ⚑, заметка пользователя) не трогает |
| `npm run render-resume -- --track vue [--lang en\|ru\|es]` | PDF резюме трека в `data/generated/base/` (шапка из `about.md`, проекты из `projects.md`). `--all` — все треки × готовые переводы; `--file <md>` — адаптированное под вакансию; `--projects a,b` — свой набор проектов; `--html` — только HTML; фото `profile/photo.jpg` — только в ru (`--photo` / `--no-photo`). Переводы и адаптацию делает агент — `playbooks/tailor.md` |
| `npm run dev` | UI на http://localhost:3000 |
| `npm run ui:build` | production-сборка UI в `app/.output/` |
| `npm run typecheck` | проверка типов скриптов и `.ts`-кода UI (`.vue` не проверяются) |

### Флаги

**`collect`**

| Флаг | Смысл |
|---|---|
| `--dry-run` | ничего не записывать (ни вакансии, ни лог, ни `seen`) — только показать |
| `--limit N` | сохранить не более N новых вакансий (на каждый источник) |
| `--file path.json` | взять ленту из файла вместо сети (отладка; только с одним источником) |

Код выхода: 0 — ок, 1 — у какого-то источника не загрузился список, 2 — неверные аргументы.

Аргументы npm передаются после `--`: `npm run collect -- remoteok --dry-run --limit 3`.

**`pending`** — `--limit N`: размер батча; `--geo`: только с неопределённым наймом из Аргентины; `--upgrade`: дозаполнение скоринга v3; `--market`: дозаполнение рыночных полей; `--paths`: только пути к файлам; `--stale`: включить несвежие (старше `freshness_days`); `--all`: без лимита и со несвежими.

**`score` / `validate`** — можно передать id или пути: `npm run score -- remoteok-1137713`. С явным списком `score` пересчитывает указанные, даже если `overall` уже есть.

**`dedupe`**

| Вызов | Смысл |
|---|---|
| `npm run dedupe -- --index` | статистика индекса (по умолчанию) |
| `npm run dedupe -- --check "Acme" "Senior Vue Developer" [url…]` | есть ли такая вакансия среди сохранённых |
| `npm run dedupe -- --groups` | вероятные дубли среди уже сохранённых (одинаковые компания+должность) |

## Ручной сбор без агента

Можно пройти конвейер руками — полезно для отладки:

```bash
npm run collect                   # фаза A
npm run pending                   # что нужно отскорить
# … заполнить поля по playbooks/scoring.md в каждом файле …
npm run score && npm run validate
```

## UI

`npm run dev` → http://localhost:3000. Сервер читает все `data/vacancies/**/*.md` в память и следит за изменениями; браузер раз в 5 с спрашивает, изменилось ли что-то (`GET /api/vacancies?since=<версия>`), и перезагружает список только при изменениях, пока вкладка видима. В списке нет тяжёлых полей (`resume_match`, `score_reasoning` и т.п.) — карточка получает их отдельно. Поэтому агент и UI могут работать одновременно.

**Вкладки** — сохранённые наборы фильтров и сортировки. Все вкладки устроены одинаково: любое изменение фильтра сразу запоминается для текущей вкладки (localStorage браузера).
Встроенные: «Все» (все открытые), «Новые» (период = последний сбор), «Выбранные», «Отклики», «Внимание», «★», «⚑ Проблемные», «Закрытые». `+` — новая вкладка из текущих фильтров, двойной клик — переименовать, `×` — удалить (кроме встроенных). Если фильтры отличаются от исходных, появляются «↺ сброс» (вернуть) и «✓ закрепить» (сделать текущие исходными).

**Фильтры:** статус (мультивыбор, значения объединяются через ИЛИ): без решения, выбрана, внимание (`needs_attention`), отклик, ошибка (`apply_failed`), ⚑ проблемные, закрытые. Закрытые (`possibly_closed`) видны только если выбрано «закрытые»; если выбрано только оно — показываются только закрытые. Ещё: скоринг (отскоренные / нет), overall ≥, профиль, источник, регион (включая «не определён»), страна компании, язык, канал отклика, занятость, стоп-факторы (или «без стоп-факторов»), зарплата (указана / нет), период (всё время / последний сбор / за N дней). Значения регионов, профилей, статусов и стоп-факторов берутся из `scripts/lib/enums.ts` — общих со схемой.

**Поиск** (`/`) — быстрый, по названию, компании, локации, тегам, summary и навыкам внутри текущей вкладки; несколько слов — должны встретиться все; не сохраняется. Если есть совпадения вне вкладки, ссылка «искать по всем» временно отключает фильтры вкладки (саму вкладку не меняет).

**Сортировка** — клик по заголовку колонки (повторный клик меняет направление); Shift+клик добавляет следующий ключ (номер рядом со стрелкой). R/S/C/O/L — сортировка по remote/startup/corporate/outsource/legitimacy. ★ всегда сверху.

**Горячие клавиши:**

| Клавиша | Действие |
|---|---|
| `a` | выбрать → `selected` |
| `u` | снять выбор / ручной отклик |
| `m` | откликнулся сам (`applied`, `applied_via: manual`) |
| `s` | звезда |
| `f` | ⚑ проблемная |
| `j` / `↓`, `k` / `↑` | следующая / предыдущая |
| `/` | поиск |

UI пишет в файл только `status` (`null`/`selected`; «📨 Откликнулся сам» / клавиша `m` — `applied` с `applied_via: manual`, отменяется только такой ручной отклик), `starred`, `flagged`, `notes`, а у вакансии со статусом «отклик» — результат `outcome` (выпадающий список в карточке: нет ответа / отказ / скрининг / собеседование / оффер; `outcome_at` — дата отметки). Статусы агента (`applied` агентом, `needs_attention`, `apply_failed`) из UI не меняются — сервер вернёт 409. Встроенные вкладки: Все, Новые, Выбранные, Отклики, Внимание, ★, ⚑ Проблемные, Закрытые; в фильтре статусов есть ★, ⚑ и «с заметкой». Перед записью файл перечитывается с диска, запись атомарная — правки агента не затираются. Кнопка **⟳ rescore** — то же, что `npm run rescore`; **✓ живость** — `npm run check-alive` в фоне (Shift+клик — перепроверить и проверенные сегодня). Файлы, которые не удалось разобрать, показываются списком ошибок. Чекбокс в заголовке таблицы отмечает/снимает все видимые одним запросом (`POST /api/vacancies/batch`).

**Устройство `app/`:** `utils/filters.ts` — фильтрация и сортировка (чистые функции, тесты в `app/tests/`); `composables/` — состояние (`useVacancies` — список, опрос, правки; `useViews` — вкладки и localStorage; `useVacancyList` — видимые строки, поиск, текущая вакансия; `useCheckAlive`, `useHotkeys`, `useToast`); `components/` — `ViewTabs`, `FilterBar`, `VacancyTable`, `VacancyCard` (+ `ResumeMatch`, `ApplyChannels`, `VacancyBody`) и мелкие `MultiSelect`, `TriSelect`, `PeriodSelect`, `SortHeader`; стили — `assets/main.css`. Pinia не используется: состояние общее на модульном уровне composables.

## Где смотреть результаты

| Путь | Что |
|---|---|
| `data/vacancies/ГГГГ/ММ/<дата>-<источник>-<компания>-<должность>.md` | вакансии |
| `data/runs/<дата>-collect.md` | лог сбора: сколько в ленте / просмотрено / отсеяно (с причинами) / известных / дублей / сохранено, причина остановки |
| `data/state/seen-<источник>.json` | известные id, включая отсеянные и удалённые; срок хранения max(90, CLEANUP_DEFAULT_DAYS + 60) дней |
| `data/insights.md` | журнал наблюдений агента |

## Если что-то не так

- `validate` ругается `scores.overall: not computed` → не запущен `npm run score`.
- Вакансия пропала из UI → скорее всего ошибка разбора YAML; она в списке ошибок в UI и в `npm run validate`.
- Сбор ничего не находит → посмотрите причину остановки в `data/runs/`; возможно, всё уже известно или вне окна (строка «окно» в логе).
- Нужно «забыть» отсеянное предфильтром (например, после правки `prefilter.yaml`) → удалите `data/state/seen-<источник>.json`.

### Отсеянные вакансии и состояние системы

Новые отсеянные записи сохраняются в `data/vacancies/` с `prefilter_reason`:
заголовок, компания, ссылка и доступная локация из выдачи, без загрузки полной страницы.
В обычных вкладках и `pending` они скрыты. Кнопка «Отсеяно предфильтром»
открывает отдельный список с причиной. «Вернуть в скоринг» сначала загружает
описание; при ошибке или блокировке страницы запись остаётся отсеянной.
Пользовательский возврат снимает географический отсев, остальные стоп-флаги сохраняет.
При расширении правил заглушки снова проверяются во время следующего сбора.

Старые отчёты сбора содержат только название, компанию и причину, без id и URL:
восстановить из них достоверные вакансии нельзя. Исторические заглушки появятся,
когда источник снова отдаст соответствующую вакансию; существующие seen-записи
не сбрасываются массово.

Панель показывает очередь, отсеянные записи, число и долю стоп-флагов,
вакансии без каналов, утечки (все fit < 30) и незакрытые строки журнала.
«Обновить журнал» перечитывает `data/insights.md`; строки с `(сделано)`
или `(исправлено…)` считаются закрытыми.
`npm run geoscreen` проверяет существующие записи без определённого hire_from_ar
по явным локациям из `exclude_location_exact` без сетевых запросов.
