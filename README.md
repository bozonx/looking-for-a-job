# looking-for-a-job

Система полуавтоматического поиска работы: скрипты собирают вакансии с площадок, агент (Claude Code / любой
агент, читающий `AGENTS.md`) их оценивает, а локальный UI позволяет просматривать и отбирать.
Подробный дизайн — `dev_docs/design.md`.

## Запуск

Требуется Node.js ≥ 23.6 (исполняет `.ts` нативно).

```bash
npm install
cp .env.example .env          # лимиты сбора и отклика (необязательно — есть значения по умолчанию)
```

| Команда | Что делает |
|---|---|
| `npm run collect:remoteok` | собрать вакансии с Remote OK |
| `npm run pending` | список вакансий, ждущих оценки агентом |
| `npm run score` | посчитать `overall` и производные поля для новых вакансий |
| `npm run rescore` | пересчитать все вакансии (после правки весов) |
| `npm run validate` | проверить front matter всех вакансий |
| `npm run dedupe` | диагностика индекса дублей (`--index` / `--check` / `--groups`) |
| `npm run dev` | UI на http://localhost:3000 |
| `npm run typecheck` | проверка типов скриптов и UI |

Обычно всё запускает агент: достаточно сказать ему «собери» (см. `playbooks/collect.md`)
или «открой UI».

## Где что лежит

| Путь | Что | В git |
|---|---|---|
| `data/vacancies/ГГГГ/ММ/*.md` | вакансии: YAML front matter (оценки, флаги, статус) + текст | нет |
| `data/runs/` | логи запусков сбора | нет |
| `data/state/seen-<источник>.json` | id, отсеянные предфильтром | нет |
| `data/insights.md` | журнал наблюдений агента | нет |
| `profile/` | личное: о себе, резюме, ответы на формы (шаблоны — `*.example.md`) | только примеры |
| `config/` | обезличенные настройки (ниже) | да |
| `playbooks/` | инструкции для агента: сбор, скоринг | да |
| `scripts/` | TypeScript-скрипты | да |
| `app/` | Nuxt-UI | да |

## Настройка

| Файл | Что настраивает |
|---|---|
| `.env` | лимиты сбора (`COLLECT_MAX_PAGES`, `COLLECT_MAX_AGE_DAYS`, `COLLECT_STOP_ON_SEEN`) и отклика |
| `config/sources.md` | список площадок, их тип и статус |
| `config/preferences.md` | предпочтения человеческим языком → правила скоринга |
| `config/weights.yaml` | веса критериев и стоп-факторы (машиночитаемо) |
| `config/regions.yaml` | приоритеты регионов |
| `config/prefilter.yaml` | предфильтр по заголовку/тегам (без LLM) |
| `config/source-priority.yaml` | куда откликаться, если вакансия есть на нескольких площадках |
| `profile/*.md` | личные данные — скопируйте `*.example.md` без `.example` |

После изменения весов — `npm run rescore` (или кнопка rescore в UI).

## Как работает сбор

Сбор двухфазный — рутину делает скрипт, агент тратит токены только на новое:

1. **Скрипт** (`npm run collect:<источник>`) забирает ленту, останавливается по лимитам из `.env`
   (страницы, возраст, N подряд уже известных), отсеивает неподходящее по `config/prefilter.yaml`,
   находит дубли (по id, URL, компания+должность) и дописывает их к существующей записи,
   новые сохраняет в `data/vacancies/` со `scores: null`, пишет лог в `data/runs/`.
2. **Агент** берёт `npm run pending`, по `playbooks/scoring.md` выставляет частные оценки, краткое описание
   и флаги, при необходимости ищет реальную ссылку на сайте компании/в ATS.
3. `npm run score` считает итоговый `overall` по весам и выбирает место отклика; `npm run validate` проверяет.
4. Агент дописывает наблюдения в `data/insights.md` и выдаёт короткий отчёт с топом вакансий.

Повторный запуск инкрементален — добирается только новое.
